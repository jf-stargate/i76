## 1. Type 10 is a separate `hlight` GEO submission path

- Original `00457FF0` calls `0048F2B0` from `00458621` / `00458751` on qualifying vehicle headlight/highlight context. The producer calls original `0045F0F0` with literal `hlight` at `004FACA0` to locate a related object by label (`004FACA0` is inside the string at `004FAC9C`, not an ordinary pointer table). When no eligible object is resolved, `0048F2B0` can unlink its effect node rather than queue geometry.
- The native `0048F2B0` producer uses source `object+0x84` (local position), `object+0x90` (radius), `object+0x5C` (GEO), the original `00472D30` view transform and `00472C10` frustum classifier, then writes work **type `0x0A`** at `0048F433`, owner at `record+0x1C`, and transformed matrix at `record+0x34`; inserts via `0048FE10` at `0048F482` or `0048F4A3`. This is **not** a second ordinary type-6 vehicle body submission.
- The original spatial dispatch pointer table at `004FACA8` contains index 6 → `0048F4C0` (ordinary pass selector), index 10 → `00490640` (distinct GEO face renderer), index 7 → `0048F570` (different highlight path). **`00490640` is executable code in the retail PE but is not defined as a function in the private v97 Ghidra listing.** Treat this as a function-boundary/annotation gap, not as a lost binary routine.
- Disassembly at `00490640` reads owner at work record `+0x1C`, geometry at owner `+0x5C`, transforms vertices via `00494DA0`, traverses GEO face records, tests per-face depth against the original double `0.0` stored at `004BE7D8`, optionally resolves named texture through `0044A290`, and routes to `00471FD0` or `004260D0` depending on `view+0x3C` backend flag. These submission branches were **not reached** by the present native scenario and their actual pixel operations are not proven by this run.
- Extended PR #32 native VCF/registered-root GTSi/bus replay instruments **original `00490640`**. Both actually enter the function and reach face-depth test `004906C0`; first tested face has transform-dependent float bit pattern `0x3A8350D9`. Original branch skips to `004907C5` for both. No material acquisition or polygon submission. The Ghidra emulator has x87 warnings and the view is synthetic: do not generalize culling outcome to retail camera or claim the highlights are absent on-screen. No artificial modification to the producer record was made.

## 2. Separate camera and spatial arena lifecycle

- The retail shell/frame source passes persistent camera context **`004C2730`** via `00403E64 → 00401C90`, which dispatches to original software `00401CC0` or D3D `00401FA0` rendering. `00405970` initializes a 118-dword (472-byte) projection/camera record using original `00472220` and copies it to `004C2730` with `REP MOVSD` at `00405A2D`. Object-follow callbacks `00405B90`, `004061B0`, and other camera mode activations update/preserve this global context. `00472D30` uses its +0x40 transform and +0x68/+0x70/+0x78 translations; `00472C10` reads frustum planes around +0xA0..+0xFC. This is stronger than manually assuming the previous synthetic identity matrix was original.
- Executed original `00405970 → 00472220` with a **controlled 640×480 viewport**, resource color mode 2, default FOV about π/2, near 1, far 150, and `param_1=0` (avoids camera-mode activation). Original code completed in **2,708 emulator steps** with populated `004C2730`. Two explicit non-original math service boundaries were substituted: `0049D400` `FSINCOS` (returns single-precision `sin` in EAX and `cos` in EDX) and the `004BA090` CRT x87 float-to-int thunk (reads ST0 80-bit value, truncates, and returns EAX). The latter converted measured 639.0→639, 479.0→479 and zeros. The frame buffer/surface state is controlled: **not** an authentic running-game camera or hardware x87 validation.
- Original **`0048F9B0` allocates global render work arenas**, called during initialization from `004033A3`, separate from camera projection. Native code, with only allocator functions `00498940`/`00499CE0` intercepted, requested sizes `370000`, `128000`, `49152`, `49152`, `2880` bytes, initialized two independent **4096 × 12-byte** work-bucket tables, and returned 1 after **73,776 emulator steps**. Checked each entry zero, source bases and advanced cursors. The producer `0048FE10` and consumer `0048FAC0` work with these globals; min/max depth state is updated by producers and reset by consumer (`0048FAC0`), not simply a single fixed camera clipping constant.
