# Retail GEO rendering and lazy-texture lifecycle — original-binary checkpoint

**Research scope:** original retail `i76.exe`; fresh read-only annotated Ghidra 12.1.4 v97 analysis, PE instruction-byte cross-checks, original x86 instruction emulation at selected boundaries. Builds on merged v2.4.0 native VCF vehicle construction; does not modify the earlier run or claim native Windows display output.

## Architectural trace and structure

1. `0048F4C0` tests a component field at `component+0x38` and dispatches a context from `component+0x1C` to `0045D100` (nonzero) or `0045D530` (zero); that test is **not** a blanket per-object alpha/transparency classifier. The two paths are different object traversal strategies, ultimately converging on similar per-section render-record preparation and dispatch logic.
2. Both passes call `004466C0` to ensure geometry variant `context[5] & 7`, traverse world-object child links at `+0x64` (child) and `+0x60` (sibling), and use `0045CBE0` to transform and illuminate GEO sections. The selected geometry pointer is `object+0x5C` and its section list is `geometry+0x14`.
3. `0045CBE0` creates **transient variable-length render records**, with `record+0x04` corner count; `+0x08` owner object pointer; `+0x0C` 15-character texture/material name; `+0x1C` section byte attribute; `+0x20` masked render flags; `+0x24..0x2C` transformed section position; `+0x30..0x3C` plane coefficients; `+0x40/+0x44` binary depth-tree links; and `+0x48` onward 24-byte corner entries holding 3 float position coordinates, 2 UV floats and 1 lighting float. This last interpretation is supported by explicit stores at `0045CEFE`, `0045CF0B`, `0045CF8F` plus neighboring native instructions. Corner ordering is reversed in the studied path. The pointer in global `g_geo_render_next_record_scratch` advances by `0x48 + n*0x18`; there is no claim that the resulting scratch region has per-record reference-count ownership.
4. `0045CB80` compares transformed section positions against a stored plane and writes one of the two depth-tree child links; `0045CBE0` also performs an inline equivalent insertion sequence. The raster passes traverse that temporary tree before polygon submission. The static 256-element pointer stack visible in both passes is not evidence of unbounded arbitrary polygon count or guaranteed malformed-input safety.
5. A render record carrying draw flag bit 2 (`0x4`) resolves its texture in `0044A290(owner, material_slot_name, render_context)`; that routine first looks up the owner/name hash slot, then returns cached VQM/MAP or, for a qualifying full-resolution context, obtains an M16 handle via `00471980`. The VQM path `004474B0` can probe `.vqm`, decode `.cbk` blocks, or fall back to `.map`, depending on resource availability and cache policy. These deeper original-code decoders are binary-static in **this** checkpoint, not dynamically replayed here; prior PIX/PAK resource studies exist in `ref/`.
6. For count 1 or 2, `00471FD0` forwards to separate point/line primitive helpers. For larger counts it dispatches through raster clip/prepare table `004F9538`, then draw/submit table `004F8D38`, keyed by flags. Neither table's full entry semantics nor visual output has been validated in this run.

## Native cache invalidation and lazy rebind

`0044A0B0` uses an owner hash at `0x00533DD8` with 113 buckets. It locates the owner group and iterates per-slot nodes at `+0x44`. On a slot whose low flag bits are both clear, it calls `00447B20` (VQM release), writes `slot+0x34 = NULL`, ORs `slot+0x3C` with `0x2`, and calls `00471B70` for the M16 release boundary. For other slots it still calls the M16 release helper but leaves the VQM cache pointer and lower flag bits alone. Existing TMT descriptor pointer `slot+0x30` is not changed on that path.

The original-instruction sequences were tested using synthetic in-memory hash tables and records, with VQM release, M16 release, VQM load and CRT string comparison as explicit service stubs. Five no-owner/missing-list/mixed-flags/repeat/collision scenarios all returned with asserted native register/memory state. A second experiment in the **same emulated state** invoked original `0044A290` before invalidation and after invalidation: initial cached hit -> cache pointer null and dirty flag -> intercepted `004474B0` re-acquire -> subsequent reuse of the cached result. The slot's TMT descriptor pointer did not change. VQM payload decode, M16 memory release, real retail graphics contexts and actual texture pixels are **not** emulated.

## Depth tree test

Two isolated original-code executions of `0045CB80` with opposite signed section positions inserted the candidate under opposite root links (`+0x40` versus `+0x44`), with 24 stepped native instructions each. **Ghidra emitted uninitialized x87 ST register warnings** in these scenarios: report this as *bounded control-flow corroboration*, not complete x87 numeric validation or demonstration of pixel-correct ordering.

## Evidence provenance and next experiment

Read-only Ghidra v97 decompilation and native instruction lists cover `0044A0B0`, `0044A290`, `004466C0`, `0045CBE0`, `0045CB80`, `0045D100`, `0045D530`, `00471FD0`, `004474B0`, `00471980`, `0048F4C0` and callees. This run commits selected opcode anchors, trace tables and replay scripts, rather than bulk proprietary decompilation or binary dumps.

**Highest priority next:** extend the merged v2.4 GTSi/bus native constructor harness so the *real GEO owner slot and retail TMT descriptors* reach the live `0045CBE0` render preparation and `0044A290` VQM/M16 acquisition. Trace the original clipping table and backend callback only after render-context initialization can be supplied accurately. Establish record ownership, material/animation reuse and real resource names without inventing new ones.

**Limits:** no real Windows rendering or complete GPU/raster callbacks; no full-frame visual result; no actual VQM/CBK/M16 pixel decoding in this checkpoint; unverified X87 edge behavior; not a source reconstruction. Existing v2.4 GEO constructor and TMT-owner data remains authoritative for that earlier scope, and this checkpoint neither changes nor re-promotes it.
