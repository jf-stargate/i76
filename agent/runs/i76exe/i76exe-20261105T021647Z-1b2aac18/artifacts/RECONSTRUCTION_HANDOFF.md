# Reconstruction-facing handoff

This run offers a complete experimental null-LUM algorithm with a stated finite conversion contract. It does not authorize maintained implementation or certify a retail CRT replacement.

`model.py:lum` consumes exactly768 raw RGB8 bytes and produces the entire65,536-byte table with recovered column-major/descending generation, first-query cache, first-minimum ties, index255 exclusion and row extensions. Arithmetic uses exact rationals with explicit IEEE rounding rather than Python float. Native original instructions and Ghidra agree on complete tables in the reported cases. Every original native conversion result also agrees. All256 byte-channel values across32 active rows produce identical converted vectors for twelve tested PC/RC modes under the finite truncation service. Intermediate rounding/spill contracts must still be preserved; this property is bounded and does not apply to gamma or arbitrary floats.

A provisional implementation can use the rational model as an oracle for the recovered generation path, provided it explicitly adopts finite truncation toward zero at the import boundary and distinguishes that decision from executing historical MSVCRT. It must keep supplied LUM copying, callback correction/entry-zero normalization, runtime column239 modification, serialized resources and generated tables as distinct operations. The context in these tests contains unmodified ACT bytes, not a measured scene-selected corrected palette. Table generation never implies equality with an existing LUM resource.

`arithmetic_contracts.json` records every constant's bit pattern, operations, spill widths, addresses, layout and service assumptions. `arithmetic_audit.json` supplies original arithmetic/control-transfer evidence. `results.json` provides complete LUM/gamma and per-gamma-row hashes; `original_comparisons.json` establishes scope of Ghidra/native execution. The services ledger identifies everything injected.

Gamma must retain an explicit unsupported retail-exact dependency. The caller supplies extended ST1 normalized base and ST0 reciprocal reloaded from binary64 to_CIpow, then multiplies returned ST0 by255 without a caller double spill. FSTP64 of the reciprocal, PC/RC, imported return precision and the integer conversion affect exact bytes. Even exponent1 need not be identity; there is no original endpoint repair or clamp. The startup requests53-bit precision through_controlfp, but the actual DLL, runtime initialization and later CW remain unexecuted. Do not choose the PC64/double hash merely because it has endpoints0/255.

Next work should authenticate the retail runtime DLL and execute its_controlfp/_ftol/_CIpow with required data, dispatch, CPU initialization and math-error services. Compare raw80-bit operands/returns and all2,560 bytes against this matrix. An observed modern pow or convenient mathematical expression cannot close that dependency. Ghidra FPUControlWord alone cannot establish x87 parity: the fixed-replay negative control proves that the relevant arithmetic ignores it.

Public changes are confined to the new run. No canonical promotion, original asset mutation, maintained C++ change or merge is proposed here.
