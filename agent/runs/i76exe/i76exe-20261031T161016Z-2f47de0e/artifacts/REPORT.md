## B — separate table, palette and material contracts

Fresh GZF xrefs identify producer callers `0047615B`, `0042DC36`, `00434606`, `00475AC4`, `0048DD56`. The first and last are annotated display selection and bitmap palette update; other caller boundaries are not defined as functions in this GZF. Actual retail call bytes, not annotations, establish these calls. The palette argument is a display/context object, not the 13-DWORD framebuffer descriptor: `004791F7` addresses +E8 and original `00479202` copies 768 bytes to `006432E0`.

`004791E0` initializes a 512-DWORD squared-distance table (signed difference -256..255) if absent, then resets a 32768-byte 5/5/5 nearest-color cache to FF. A null second argument calculates table entries. A nonnull argument instead copies **65536 bytes** with `0047924C`; a supplied LUM branch is therefore distinct from calculated entries. Native palette copy, square table and cache initialization hashes are independently checked. The table is static image storage `[0061B2A0,0062B2A0)`, not a recovered heap allocation. Only its first 8192 bytes are addressed by this callback's row mask `1F00` plus color byte. The diagnostic fixture size from PR77 is not the full producer ownership size.

Each column has 32 calculated rows and 224 endpoint-extension rows. Original writer PCs: `004793A4` writes rows31..8; `004794AF` rows7..0; `004794ED` copies row31 into rows32..143; `0047950B` copies row0 into rows255..144. All addresses in this experiment have low index byte zero. The verifier requires the exact 256-store chronology and final column bytes, with no overlap or missing row. Other columns are ungenerated and never consumed by this experiment.

Original `004796A0` searches palette entries 0..254 (strict end address `006435DD`) and caches the first answer per quantized input cube. The first minimum wins equal-distance ties. Replacing that cache with independently recomputed nearest color for every query would be a different algorithm.

The experiment directly invokes the producer and preserves m02.act's entry0 triplet (1,1,1); it does not execute those normalization/update routines. Backend-specific function-pointer binding and actual source LUM choice are unresolved. `00478B80` can later overwrite one full table column via a separate integer ramp; WinMain references it. No such update is executed here. Xrefs also show other raster consumers and display lookup construction; this is not exclusive ownership by CB00.

GEO constructor `00446C90`, call `00446F44`, passes three source section bytes at +8/+9/+A to the nearest-color helper and stores its result at runtime section+8.
