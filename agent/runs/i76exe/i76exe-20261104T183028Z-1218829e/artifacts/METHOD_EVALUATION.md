# Method evaluation and final assessment

## 1. Can structure discover the same major resource neighborhoods without identities?

Partially. A pre-comparison model using only physical addresses and reference sets places both wrapper edges (004703A0, 00470660) in its invariant top five, and detects the later utility transition at 00470CD0. Shared-write families distinguish cache accounting, repeated name scratch and index arrays. Those neighborhoods agree with both manually grouped pilots. It also elevates a stateless facade and a comparator callback, and generates too many threshold cuts. It discovers structural neighborhoods and transition zones, not exact original compilation units.

There is no labeled original-file ground truth, so no precision, recall, accuracy percentage or confidence percentage is justified. Matching earlier semantic hypotheses is not ground truth. Twenty-two functions in one selected resource region are not a representative executable sample.

## 2. Which signals are strongest?

A sustained switch between independently observed mutable-state families, with repeated local consumers and matching initialization/release instructions, is strongest here. The three scratch wrappers are internally coherent even though they do not call each other. Index setup writes the cells consumed by teardown and searches. Whole-program user counts prevent treating global mode state as private scratch. Original address-taking is especially important counterevidence for seemingly disconnected helpers.

These signals support local cohesion or a dependency seam. Original source separation remains weaker because exported globals, one large file with several responsibilities, headers/copying, function-level linking and compiler/linker ordering can produce the same pattern. No object contribution, debug/source record, static symbol or recovered filename discriminates these explanations.

## 3. Which signals are unreliable or correlated?

Absence of a direct call is unreliable: 00470CA0 is a shared escaped comparator. A function with no globals can be a private helper, not a standalone file. Caller turnover can merely distinguish operations in one coherent interface. State turnover, shared-state graph density and adjacent linkage count related evidence; they are not independent witnesses. Three overlapping scratch addresses can inflate apparent feature multiplicity. Initialization and release naturally call different services. String pooling crosses files; readonly import slots reflect API use rather than original string ownership. Writable memory does not by itself imply mutable semantic state.

Every local entry is 16-byte aligned and all internal gaps are NOPs, yet their ranks vary widely. The out-of-region control gap is mostly switch tables/maps. Ghidra-defined-function gaps may even contain disassembled, unassigned functions (00470D40/00470D90 context). No gap bonus is justified.

Reference extraction is incomplete for aliases, heap fields, arithmetic addressing, unresolved indirect calls and undefined object extents. Counts exclude references with no defined-function owner from function-user denominators; those raw references remain private. This can overstate exclusivity. Current semantic names and annotation types are not original symbols. The detector uses data types to recognize text but never function names, manual memberships or semantic group labels.

## 4. How sensitive are proposed boundaries?

The baseline plus twelve one-weight ±20% alternatives and windows 2/4 give 15 rankings. The top-five set is invariant: 00470660 ranks 1–3, 00470CA0 1–2, 00470CD0 2–3, and 004703A0/00470340 4–5. This narrow parameter stability is real, but it does not rescue the comparator error. Equal saturated scores of 4.5 for three cuts are resolved by address, not meaningful source evidence.

Lower proposals are less stable: 0046FFC0 moves from ranks 7 to 17; 004704A0 from 7 to 16; 0046FEE0 from 13 to 21. They are not top-five proposals under any tested variation. The fixed-weight thresholds 1.5/2.0/2.5 generate 13/7/6 cuts respectively (14/8/7 bounded fragments). Their abundance demonstrates threshold sensitivity and oversegmentation; none is an estimated count of original files.

Model-definition changes matter more than small weight changes. Separating import pointers from text/readonly constants and adding callback edges moves 00470CA0 from rank 2 to 6. This is explicitly post-freeze exploratory evidence. A future model should preregister those corrections and test new regions; retesting the same region would not be independent confirmation.

## 5. Are original source-file hypotheses more credible than functional grouping?

Not meaningfully enough to assert original files. The method adds evidence that neighborhoods are recoverable without semantic labels and that state ownership is sustained across local functions. It strengthens particular *structural* seam hypotheses beyond handpicked group scoring. It does not distinguish a source-file seam from ordinary adjacent functional grouping within one file. Original filenames and memberships remain unresolved.

Keep four separate judgments:

| Question | Result here |
|---|---|
| Structural boundary likelihood | 004703A0/00470660 are defensible high-priority seams for investigation; 00470CD0 plausible utility transition; 00470340 ambiguous; 00470CA0 misleading as a clean split. These are ordinal judgments. |
| Internal functional cohesion | Strong repeated scratch and index lifecycle relationships; cache state bridges setup/eviction/API phases. |
| Probable original source-file separation | Plausible at sustained transitions, unverified; broad single-file and shared-extern alternatives survive. |
| Preferred modern reconstruction modules | May follow cache, facade, texture-name and index interfaces, with explicit shared key utility. This design choice is not historical evidence or authorized implementation. |

## 6. Expand to all 2,102 defined functions?

Do not partition all 2,102 now. Extraction can scale, but ranking a larger graph would multiply known false positives and unrecognized-function/alias problems. First use preregistered held-out contiguous regions containing callbacks, thunks, shared extern state, jump tables and small helpers. Include order-shuffle or topology-preserving null controls and compare weighted-state features against simple call-only/state-only baselines. Audit object normalization and unresolved-reference rates. Freeze each model before external comparison. Expansion is justified as bounded falsification experiments, not a whole-executable source-file map.

## Reproduction, validation and unresolved work

The public-only standard-library reproduction regenerates exact ranks and report bytes from compact bounded features. Licensed private inputs plus Ghidra 12.1.4 reproduce the extraction and compare body hashes with retail section mapping. The read-only replay has identical exported content; extraction modification counters are 2→2 at import and 3→3 after save/reopen. The inter-session counter increment is framework import/save bookkeeping, not claimed byte-identical database serialization. No script calls a mutator; the read-only replay is not saved. Input hashes are rechecked. These checks test provenance and extraction, not original file membership.

The blind model intentionally remains frozen, including its broad `literal` bucket and omission of scored callback edges. Published data_taxonomy.json and postfreeze_ablations.json expose those defects. Private full capture, program database, logs, executable and original GZF stay outside GitHub. Canonical manuals and migrations remain untouched.

Remaining unknowns include actual compiler/linker function contribution policy, private/static versus external linkage, completeness of indirect reference recovery, original comparator ownership, unrecognized function extents in context, behavior under other windows and state representations, and validity outside this selected resource neighborhood. No full partition or original filenames are proposed.
