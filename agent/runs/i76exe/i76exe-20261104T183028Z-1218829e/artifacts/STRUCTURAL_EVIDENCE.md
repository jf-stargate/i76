## Physical layout, references and ownership limits

Every extracted entry is 16-byte aligned. All 21 internal gaps are 1–15 bytes of 0x90 padding, independently checked against the PE; there are no internal jump-table gaps in this bounded resource region. The largest internal gaps (15 bytes before 0046FFC0, 004703A0, 00470C40) occur at very different ranks. One-byte gaps occur before both 00470580 and 00470660. Alignment/gap magnitude cannot discriminate these cuts.

The immediately following defined context function at 00470D30 is only six bytes. The interval until the *next defined* function at 00470ED0 includes original instructions beginning at 00470D40 and 00470D90 (the latter returns at 00470ECD). This is disassembled code lacking defined function entries, plus padding, not a giant object separator. It is outside the ranked interval; its apparent gap is retained in gap_summary.tsv to expose the defined-function blind spot. We do not create functions or change annotations.

Post-freeze external negative control: 00412830 ends at 00412C2F; the 144-byte interval to 00412CC0 contains five three-entry pointer jump tables beginning 00412C30/4C/68/84/A0, byte-index maps, and only four trailing NOPs at 00412CBC–BF. Original computed jumps at 00412916, 00412930, 00412958, 00412A22 and 00412BDD index those tables; e.g. 00412916 jumps through [ECX*4+00412C30]. This control was suggested by the prior pilots after the freeze and independently rechecked, not used to tune discovery. It confirms why gap bonuses were excluded. It says nothing about whether the surrounding functions came from one file.

Relevant data objects have whole-program direct reference users, including interior offsets of defined data. Cells 00609580 (8 defined users), 0060958C (7), 00609590 (6), 00609584 (4), 00609588 (2) and 00609594 (5) are not restricted to a handpicked API core. Scratch addresses 0058D908/C/D each have three defined users, all wrappers; these are overlapping pieces of one inferred buffer, not three independent linkage witnesses. Index cells 0058D91C/920/924/928 have 6/4/2/5 defined users, all in the examined index neighborhood. 00654B80 has 21 defined users, many external to the region. Flag byte 00609520 has four defined users and an external writer at 0047129D. Counts are observations about references; none proves file-static linkage, and pointer-based consumers may escape detection.

Defined text and pooled-string addresses are distinct from mutable state. Writable text still counts as text. Unwritten undefined storage (e.g. suffix table base 004F8AAF and 005C3A20) stays uncertain. The frozen broad `literal` bucket also included read-only import pointer slots such as 004BC148/004BC28C; data_taxonomy.json distinguishes them explicitly. They are executable API dependencies, not pooled strings. A post-freeze ablation excludes these slots rather than silently relabeling the blind result. No pooled-text content is a scoring input. String pooling can cross object files; nearby strings are not source provenance. Interior string reference 004F8AB8 normalizes to its containing string 004F8AB0.

No extracted function is a Ghidra thunk; no inter-function direct jump/tail edge was identified in the ranked region. This is absence in this definition/reference baseline, not proof that no tail call exists. IAT and register-indirect calls are preserved as original instruction evidence; resolved external call references enter target overlap, but unresolved register calls have no target. No original persistent callback-pointer table into these 22 entries was found among their incoming references: comparator pointers are pushed from code. The original switch tables above are explicitly distinguished from callbacks. No synthetic callback tables were invented.

Scratch address 0058D908 is passed to external copy/format code and then texture services (00470420, 0047046D), so its address escapes. Index allocation pointers are written to 0058D91C/20 and later passed to searches/frees; they are not inferred static merely from low direct-reference counts. Release relationships and imported code dependencies supply cohesion without recovering C/C++ linkage, original filenames or compiler object contributions.
