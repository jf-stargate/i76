# Triangle fallback and anchor

## Anchor priority

Let A,B,C,D be leaf edges +0C,+10,+14,+18. The scan at `00491BE4..00491C12` checks A,B,C,D in that order. Select the first edge whose +04 child exists and whose **both children are terminal**. Use the signed int16 endpoint +02 of the first child, which is that edge's midpoint.

If no such edge exists, follow the exact priority at `00491C14..00491C79`:

| Condition | Selected endpoint |
| --- | --- |
| A terminal, C terminal | C.start |
| A terminal, C split, D terminal | D.start |
| A split, B terminal, C terminal | C.end |
| A split, B terminal, C split, D terminal | D.end |
| Otherwise | Additional-center path |

The midpoint scan precedes every corner test. It is not a first-boundary-vertex or maximum-height heuristic. Primary executes 20 midpoint anchors and 59 C.start anchors; contrast additionally executes one D.start anchor. No C.end or D.end selection is observed in the tested corpus.

## Additional-center path

The branch begins at `00491C7D`, after the midpoint scan fails and either (A and B both split) or (C and D both split) prevents corner selection. This Boolean expression is conditional on the earlier scan finding no shallow split edge.

Binary-static arithmetic: save the old global vertex count as anchor and increment `006442EC`. Let P=A.start, Q=B.end. Append float32 `(viewXYZ[P]+viewXYZ[Q])*.5` to the transformed XYZ buffer, and corresponding averages of aux+00/+04. The shown path does not initialize aux+08. This is a view-space diagonal average, not a new terrain height sample or an appended edge node. It occurs before whole eligibility and may therefore create a vertex even if the whole attempt later succeeds.

No one of the 20 original-instruction scenarios reaches it. The real adaptive graphs always offer a terminal-child midpoint or permitted corner. This is the concrete blocker: no authenticated leaf graph satisfying the preceding conditions has been generated by these camera/LOD configurations. The predictor raises `NotImplementedError` for this case. No synthetic leaf, expected acceptance, new source height, high-color aux value, or claimed authentic hit is invented. C.end/D.end are similarly static-only pending a genuine graph.

## Ordered fallback

At `0049209C`, walk adjacent pairs `(loop[i],loop[(i+1)%N])` in flatten order, including the closing pair. If either endpoint equals the selected anchor, skip the pair entirely. For every remaining pair, compute and save the plane for `(anchor,previous,current)` at `004920E8`.

Only after computing **all** candidate planes does the second pass begin. Visit the same eligible pairs in the same order. A candidate with d>=0 makes no emitter call. For d<0, compute scalar shade (or use zero under the high-color flag), write the anchor into the slot preceding the adjacent pair, and call the emitter with three indices `(anchor,previous,current)`. Saved planes protect this sequence from the in-place index-array overwrites. Ordinary emission then copies those indices in reverse into work records.

`00492225` is followed only by stack cleanup and progression; the returned EAX is ignored. A triangle rejection neither retries the whole polygon nor stops subsequent triangles. In contrast, `00492094/96` explicitly checks the whole call result: only zero permits fallback. Original ordinary emitter returns zero on zero clipped count, one after a positive clipped count and its bin insertion call. Its return is not the bin routine's acceptance result.

Primary: 54 fallback leaves produce 125 non-anchor-adjacent candidates; 13 fail facing, leaving 112 triangle attempts. The independent trace predicts all skipped candidates, emitted index triples and their exact order; original plane-call signs and emitter events corroborate the filtering. See `evidence/decisions.jsonl`, `evidence/verification.json`, and sparse instruction anchors.
