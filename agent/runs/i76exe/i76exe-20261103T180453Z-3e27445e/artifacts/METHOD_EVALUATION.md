# Method evaluation

Reliable recovery is limited to plausible cores and structural seams, not exact original files. No direct source provenance or independent ground truth was recovered. Eight cores contain 32 of the 42 bounded functions; ten remain unassigned. None receives HIGH confidence. A function being in a MODERATE core does not mean its precise source attribution is established.

Code layout preserves useful local lifecycle/state neighborhoods (PIX setup/teardown/use, execution reset/dispatch/interpreter/scheduler, texture wrappers). It does not establish a one-file-per-subsystem layout. Shared distinctive mutable state plus initialization/consumption relationships discriminates best. Internal private calls strengthen the registered-source and FSM import chains but fail for the terrain and PIX cores, which have zero internal direct edges. Broad external-call interfaces are common.

Misleading signals include semantic names, common error reporter 0042D5D0, CRT allocation/copy calls, ubiquitous constants, interned strings and address proximity. Five correlated uses of one page grid are one state-ownership signal, not five proofs. Strings help identify lifecycle purpose but are weak TU evidence: pooling and diagnostics cross files. Caller counts omit callbacks, tail jumps and indirect dispatch and are counts of functions, not call sites.

Compiler/runtime utilities are visible as shared out-of-region callees (e.g. 004BA090/004BA290 and imported services); this pilot does not establish their original file extents. The 00493150 JMP thunk is a concrete generated/forwarding-code caveat. PE linker version 5.10 and a structurally valid Rich record are compilation metadata, not proof of a specific compiler optimization policy. Final merged sections do not preserve per-function COMDAT provenance. Function-level linking, COMDAT folding/order, static-library extraction and possible interprocedural optimization cannot be excluded. No optimization mode is inferred from names or address order.

Do not launch whole-executable clustering yet. Extending extraction coverage is inexpensive and already done privately; extending source ownership claims is not justified by these qualitative results. Next examine bounded flanks, normalize data to owning objects rather than individual byte xrefs, classify writes versus reads, resolve callback registrations and tail calls, inspect static-initializer order and jump-table gaps, and seek original MAP/PDB/OBJ/library artifacts or matching compiler test binaries. A second targeted pilot with these controls is justified. Whole-executable clustering could later propose review candidates, but could not validate its own accuracy. No accuracy percentage is warranted.

Reproduction uses Ghidra Java and Python standard library only. Inventory walks every defined body address and emits reference types, source/target addresses, strings and body sets. Analysis resolves numeric direct-call targets against exact defined entries, computes consecutive-body envelopes and bounded data intersections; it never partitions all functions. Stack/external-address references remain in private inventory; bounded audit resolves external targets and code/function-pointer references. No decompilation or resource payload is exported publicly.
