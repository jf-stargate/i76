# Visibility points, ordering and vertical planes

Finding ROOT-HULL; S/E/H/D as defined in CAMERA_TERRAIN_ROOT.md. Primary
`004929B0`, angular operation `00492EAF`, plane builder `00492890`, reciprocal
square root `00495000`, table initializer `00493C50`.

## Duplicate filter and angular selection

Process camera plus four projected points in their original order. Reject a point
if its X/Z squared distance to **any later** point is strictly less than `.25`.
This preserves the later representative of a close pair; it is neither a
coordinate-key set nor greedy filtering against retained points. It uses all
later original points, even one that will itself be rejected. The threshold is
half a lattice unit (2.5 world units). `00492D5C` captures each keep decision.
Fewer than three survivors returns zero at `00492D98`, after root stores.

Choose the survivor with minimum Z, resolving ties to the **last** survivor
(`<=`). Append a duplicate of that start point as a closing sentinel. For each
output slot, swap the selected survivor into that slot. From the point just
placed, score every remaining slot including the sentinel:

```
dx = candidate.x - current.x
dz = candidate.z - current.z
angle = FPATAN(dz, dx)          # x87 atan2, radians
if angle < 0: angle -= -2*pi
score = double(dxStored*dxStored + dzStored*dzStored + angle*10000000)
```

The original differences are retained for FPATAN while copies are spilled as
doubles for squared distance. Keep the candidate with smallest score strictly
between the preceding selected score and `125663706.14359173` (4*pi*1e7).
The lower bound begins at zero and is never reset between output slots. Equal
scores are excluded. Stop when the selected slot is the closing sentinel; do
not emit it. The loop falls back to that sentinel if no candidate qualifies.
The primary retains camera plus the later member of each close far-corner pair,
then emits three points. Rotated controls retain/employ five points.

This algorithm does not perform an ordinary cross-product convex hull, orientation
pop loop, area rejection, or standard lexicographic angular sort. In particular,
the controlled collinear input is **accepted** and produces three vertical
planes. Do not silently replace this with rejection of zero-area polygons.
Large distances can compete with the angular term; behavior outside the measured
finite local domain is not validated.

`angle_instruction_service.tsv` records both input ext80 registers and the
hardware FPATAN result substituted only at Ghidra's unsupported instruction.
Native H executes the original FPATAN without interception. NumPy extended atan2
in D produced exactly the observed stored double scores in these cases;
this does not prove all transcendental inputs or platforms bit-identical.

## Vertical plane construction and inward orientation

For each hull point p in output order, q is the preceding point, wrapping the
first to the last. Make r=(p.x,10,p.z). `00492890` computes
`cross(q-p,r-p)` and normalizes it with original approximate reciprocal sqrt.
The unnormalized vertical coefficients reduce to `nx=0-10*(q.z-p.z)`,
`ny=0*(q.z-p.z)-0*(q.x-p.x)`, `nz=10*(q.x-p.x)-0`.
Preserve subtraction/signed zeros. A sign-shortened `-10*dz` already disagrees
with original zero bits in the controlled collinear/axis-aligned fixtures.

Cross components are spilled as doubles; squared magnitude is stored double
before `00495000`. This helper uses a 256-byte exponent/mantissa seed table,
one Newton step `(.5*y)*(3-magnitudeSquared*y*y)`, and double factor `1.00001`.
Table initializer constructs double high words `(i|0x1ff00)<<13`, low word zero,
computes `1/sqrt(value)`, adds `0x400` to the high word, shifts 12 and takes a
byte; entry 128 is forced to 255. D generates this table mathematically; it
does not copy original table bytes. The generated bytes match the observed table.
In `00495000`, seed high word is
`(((0xBFC-(inputHigh>>20))>>1)<<20) | (table[(inputHigh>>13)&255]<<12)`.
Low word is zero. Do not replace this helper with exact `1/sqrt`.

Store normal XYZ as float32. Compute double offset from the **unrounded
extended** normal dot p with a minus sign. There is no float32 normal reload
before this offset calculation. Records are 24 bytes: floats at +00/+04/+08,
an incidental upper half of a former Y-difference double at +0C, double offset
at +10. Padding is zero in every measured record; it is not a fourth normal.
The original ny retains signed zero.

Compute the hull mean X/Z in extended precision, store means as doubles.
Evaluate `storedFloatNx*meanX + storedFloatNz*meanZ + doubleOffset` in x87.
If negative, negate stored nx, nz and offset; **do not negate ny**. These inward
planes are written at `00644308`, count at `006442F0`. They are distinct from
the camera's six 3D frustum clipping planes. They operate in terrain lattice X/Z.

## Downstream contract

Keep #140's `004911E0` consumer: for half-size <32, test distance from the quad
center with radius `halfSize*1.42`, retaining both original signed comparisons.
No normalization or conversion to world coordinates is added here.
`check_downstream.py` imports the unchanged accepted independent Model/predicate,
supplies only newly predicted root/camera/threshold/planes, then compares source
and complete interleaved arena bytes. All 20 emulated accepted scenarios match,
including the nine known #140 source graphs. Three rejected cases generate no
source graph; `clear_exact` has no comparable emulated graph after its numerical
admission discrepancy. This does not establish walker shading, final emission
selection, rasterization or arbitrary-scene parity.
