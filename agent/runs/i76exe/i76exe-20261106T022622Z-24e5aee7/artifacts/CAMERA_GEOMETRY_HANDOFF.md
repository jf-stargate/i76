# Camera geometry reconstruction handoff

The external root/visibility inputs required by accepted #140 can be replaced
within the measured M06 domain. The model starts from the same constructed
camera/view record; camera scheduling, physics and mission poses remain supplied
or original. Terrain quality and an authenticated independent height provider
are required configuration/data dependencies, not original precomputed geometry.
Research only; no maintained C++ changes or self-merge authority.

## Proposed interface and operation order

Use project-owned types representing camera double position and four world
frustum corners, float projection scale/tangent, signed viewport width, terrain
step/reciprocal and quality. An independent bilinear-height sampler implements
#141's coordinate and x87 store contract. Return a tagged accepted/rejected
result, optional root X/Z/exponent, ordered double X/Z points, and vertical
planes with float XYZ and double offset; return the two float32 thresholds and
float32 LOD camera X/Z separately. These are proposed types, not recovered names.

1. Compute threshold chains and float32 camera lattice coordinates.
2. Sample world height, compare double camera Y with native extended height.
3. Form five projected points; conditionally perform the all-corners<=0
   intersection branch; compute bias-rounded extrema and expanded root.
4. Filter close points against later inputs, select the ordered hull with the
   recovered score/sentinel procedure, then build and orient vertical planes.
5. Supply predicted root, planes and thresholds to the unchanged bounded #140
   shared-edge/source builder and its original subdivision predicate.

Do not implement root bounds via floor, a standard convex hull, normalized exact
planes, per-operation float32 arithmetic or a terrain-height raycast. Each can
change behavior. Preserve output count versus storage separately on rejection:
retail rejection does not uniformly reset earlier globals. A reconstruction
should expose explicit validity instead of reusing stale data, documenting that
intentional representation improvement.

## Evidence and result ledger

`camera_fixtures.json` separates original camera inputs and sparse licensed-height
stencils from E and H observations. `predictions.json` is generated by independent
code that takes only the input subobject. `comparison.json` reports exact normal
bits, double offsets, score ULPs and admission diagnostics. All 24 H observations
match D for admission, written root fields, threshold bits and all plane bytes
(including signed-zero normals and measured padding). E agrees except one
near-threshold sampler rejection. E ordered hull points, filtering and scores
match D exactly whenever recorded. Tolerances allowed by the comparator are
reported explicitly: <=4e-12 absolute for double X/Z, <=2 double ULP for scores,
<=16 double ULP for offsets. **Measured maxima are zero**, not merely within
those tolerances. Normal and threshold bits and root integers require equality.

`downstream.json`: 20 accepted E source graphs/complete edge-leaf arenas match
the independent model with predicted inputs, including all nine #140 valid
scenarios. Three common rejected cases have no graph. `clear_exact` is accepted
by H/D but E rejects before graph construction; downstream parity for that case
is unavailable. Native execution covers camera-root/plane/threshold arithmetic,
not native topology. The public nine-case crosswalk compares source and arena
SHA-256 against #140's accepted published hashes.

## Remaining scope

Full pose-to-view reconstruction, arbitrary viewport/FOV combinations, exceptional
FP state and values, overflow/negative root extents, singular intersections,
out-of-domain/default height state, repeated rejected-frame global lifetime,
allocator exhaustion, native full topology, walker added-center branches,
facing/shade selection, successful alternate materials and raster/pixels remain
unverified. A checked reconstruction should define unsupported-state behavior
instead of adopting the original unchecked memory and nontermination risks.

The isolated run should be reviewed together with merged #140 and #141 before
promoting a camera-complete adaptive-source milestone. Publication does not
authorize renderer or maintained reconstruction edits.
