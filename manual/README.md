# I76 manual — curated project documentation

`manual/` holds curated reference, decisions, roadmap, and accepted history. Agents may propose edits on isolated branches; promotion into accepted documentation requires explicit maintainer review. Cite immutable run evidence, not unverifiable prose.

The legacy `ref/` tree remains a preserved historical checkpoint, not a living target for routine generated documentation. The maintainer-designated repository/documentation steward generates updates to `manual/reference/` from merged research evidence and explicit promotions at subsystem milestones, through separate reviewed PRs. Research conversations provide documentation-impact handoffs inside their owned immutable runs. See [documentation workflow](roadmap/DOCUMENTATION_WORKFLOW.md).

## Proposed planning hierarchy

For maintainer review (not yet adopted as an authoritative project charter): [project objectives](roadmap/PROJECT_OBJECTIVES.md) define desired outcomes and unresolved strategic choices; [capability roadmap](roadmap/CAPABILITY_ROADMAP.md) maps them to demonstrable integration gates; [ENG/VEH/TER research milestones](roadmap/ENGINE_SUBSYSTEM_MILESTONES.md) define bounded technical investigations. Codex run IDs and merged evidence are distinct from milestone approval.
