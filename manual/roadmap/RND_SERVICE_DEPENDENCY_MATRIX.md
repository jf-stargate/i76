## 1. Scope, evidence classifications and the meaning of a boundary

This document answers **what original retail instructions actually ran, what the emulator or host supplied, and which observation survives each substitution**. It reconciles already merged research and the accepted [M06 terrain reference][M06REF], [software-renderer reference][RNDREF], [RND milestones][MILESTONES], [image-oracle plan][ORACLE], and [promotion records][P78], [P79], [P83], [P84]. It does not promote any new facts beyond them. Source instructions, trace rows and guarded writes outrank explanatory function names; recently delivered v98 naming files are annotations, not a new execution tier.

- **O (original-executed):** authenticated retail x86 instructions retired under Ghidra EmulatorHelper in the named run. Qualify **entry**, **last instruction**, **RET**, and **host boundary stop** separately; an original caller with a host-handled callee is not proof the callee ran.
- **S (binary-static):** original PE/GZF instruction bytes, dispatch cells, constant or xref inspected but not reached on that positive execution path. A named function or presumed dispatch mode is not O.
- **D (independently derived):** source-backed Python verifier, byte reconstruction or numerical comparison. It may confirm O's expected effects but is not an additional original execution.
- **X (external/controlled):** licensed fixture bytes exposed through a service; manually selected object/pose/palette; memory mapping/initial fill; a stub, CRT/OS/numerical return; an exact host `memcpy`; or test-constructed expected pixels. Original instructions may subsequently write into X-owned memory.
- **U (unresolved):** no accepted execution or authenticated provenance for the proposed original behavior. Unreached code is not classified as having failed in retail Windows.

**Private provenance** is recorded by accepted manifests, not remeasured in this documentation pass: retail `i76.exe` MD5 `a640ea0097dbb62e0c77b7f2847c7161`, SHA-256 `bc073a930da5b03793c086f22eeeff6f2cc7d9c81ce650c6656d0d0c49af13f3`; `I76.ZFS` SHA-256 `0610541842dfd10464ea02307dec9749ac2b31da4019e1af05d5fcfc55d9020d`; annotated Ghidra 12.1.4 `i76_mission_v97_verified_names` baseline SHA-256 `b2f76177fbab3d6ddc8c88cb10eac5d331b52155190e120c349508f6032d4fce`. M06 `miss8/M06.MSN` and `M06.TER` SHA-256 are respectively `923d47e189e087b604e7b2d2825668433b9ccf1547437938fd31b5573202a97f` and `fdd18c8b8a4dc1b280ae5ccf780b988a928cadbcf9170cd8c1907da97e4002ea` ([M74][M74], [M76][M76], [M80][M80]). Original PE/ZFS/M06 files and private GZF are not present in this assignment. The accepted runs *report* private fresh-project reproductions; none was rerun here.

## 7. Integration and invalid-evidence risks

1. **Reset and scheduling:** #80 deliberately calls original stage bodies in frame-site order (terrain `00401DE1`, visibility `00401E2C`, consume `00401E8D`), not the complete `00401CC0` frame with roads, effects, HUD, sky, device and timing. Do not reset `0048F9B0`, buckets, cursor, source buffer or camera between producers. Conversely, do not assume subsequent frame zeroing without tracking original writer PCs.
2. **Scratch aliasing and pointer identity:** #80 `005DD2EC = 005DD320 + 0xD2F0` shares storage, unlike #74/#76's diagnostic disjoint regions. Reusing source scratch after a copied queue polygon is permissible **only** if byte snapshots/ownership show the queued record no longer references it. A host copy/restore between runs is not native frame continuity.
3. **Palette, cache and color binding:** source ACT is selected in #81 by harness and need not belong to M06. Original scene updater may change entry0, the squared-distance/nearest cache and all 65,536 table entries; the `00478B80` ramp can overwrite a column. Reusing a shade column or cache from another emulator, or claiming GEO-time native nearest-color when its stub remains, invalidates material-color conclusions.
4. **x87 and CRT:** original source arithmetic plus bounded Java/C conversions is not the same as executing an imported MSVCRT helper or CPU hardware exception/tag state. Preserve `ST0..ST7`, FPU CW/status, original caller ESP/return, signed width, spill points, distinct FISTP/FPATAN helpers and finite input domains. Compare byte-exact integer/owner/pointer claims separately from local float32 ULP-tolerant projections. Unexpected NaN/overflow is partial/invalid, not quietly rounded.
5. **Framebuffer and command ownership:** #75 commands and pending packed span are not yet pixel output. #77 raw allocation with zero heap handle is diagnostic X despite original descriptor/pixel stores. Verify pitch, base, X/Y offsets, address-bound and guards *per store*, and identify whether surface teardown `00474D40` actually executed. A framebuffer SHA is not original device presentation.
6. **Source provenance:** distinguish actual private hashes, archived manifest hashes, source raw GEO/TER/ACT bytes, emitted probe events, independent recomputation and historical PR descriptions. The v97 GZF names and subsequent v98 renamed annotations cannot alone prove reachability. Reject mismatched PE/GZF/ZFS/M06 hashes, historical stale viewport near/far labels and absent/optional resource returns mistaken for valid texture output.
7. **Cross-state splice:** #80's unified producer/consumer and #77/#81's separate native bus raster are independently successful **in different emulators**. Concatenating their records, addresses, spans or expected pixels **must be rejected** as evidence of one original same-state native terrain+vehicle frame. A future integration must preserve one original memory map, original camera, scratch/palette/arena state, original selected dispatch and new original byte-store chronology end to end; independently generated expectations are only D controls.
