## Four levels of planning

```text
Project objective  (why / desired outcome)
  -> capability gate  (demonstrable end-to-end behavior)
     -> technical milestone  (specific missing interface or dependency)
        -> immutable Codex research run + PR  (bounded repeatable evidence)
```

Each capability must state a demonstration scenario, independent check, original-versus-supplied service ledger, dependencies, evidence status and completion boundary. A successful run may be **necessary but insufficient** for capability acceptance. A green `integrity` check does not prove scientific correctness, and a merged run is not automatically a curated reference.

## First integrated engine scenario

**Provisional target:** authentic retail M06 mission and stock player vehicle; deterministically reproduce a meaningful sequence from mission resources through registered object, original clock and frame phases, selected control effect, environmental interaction and inspectable camera state. Stage the work through original-instruction Ghidra execution with supplied and clearly labeled OS/hardware/resource services, then independently validate selected state/event traces.

An original dispatcher frame is an intermediate gate; full Windows execution, native final pixels and complete polygon collision are **not** assumed at that gate. The ultimate first demonstration's live-input/visual requirement awaits maintainer decision.

A merged research milestone is neither an automatically closed capability nor a full original Windows runtime.

## Task-selection procedure for the coordination layer

1. **Live bootstrap:** pin new protected `main` SHA; read the version-matched [AGENTS](../../AGENTS.md), [protocol version](../../agent/protocol/VERSION), [bootstrap](../../agent/protocol/BOOTSTRAP.md), [access policy](../../agent/protocol/access.yaml) and [documentation workflow](DOCUMENTATION_WORKFLOW.md). Inspect ruleset/current required checks, existing branches/open PRs and current merged-run/promotions inventory. Do not rely on historical enforcement snapshots or infer local session status from the absence of a PR.
2. **Select the gate before the experiment:** use the [human-ratified objectives](PROJECT_OBJECTIVES.md) if ratified; otherwise label provisional prioritization. Distinguish accepted bounded evidence, partial capability, blocked dependency and not authorized. Choose the smallest independently testable interface or lifecycle handoff, not the newest convenient label.
3. **Crosswalk evidence:** locate exact immutable `manifest.json`, `findings.json`, `validation.json`, original opcode/baseline and private-input hashes, service substitutions, report, controls, original vs independent verifiers, and any **separately merged** promotion and reference. Resolve contradictions and use the narrowest supported claim; no local reproducibility rerun is implied by this coordination document.
4. **Assign bounded independent work:** check the current [RND M-RND-12..17 dependencies](RND_SUBSYSTEM_MILESTONES.md), [ENG/VEH/TER queue](ENGINE_SUBSYSTEM_MILESTONES.md) and [subsystem indexes](subsystems/README.md). A worker specifies original addresses, exact scenario, source/fixture provenance, authorized substitutions, positive/negative outcomes, exact end boundary, fresh owned run ID and PR. Do not reuse/rename completed milestones or edit merged runs.
5. **Distinguish decisions:** research execution is one worker's run; technical promotion is a separate steward/human-reviewed PR; RND-v1 or capability acceptance is an explicit reviewed decision; proprietary inputs and maintained reconstruction need separately authorized treatment. A passing `integrity` status certifies neither science nor product readiness.
6. **Reconcile again at handoff:** compare the proposed canonical diff with newest main and accepted source evidence; validate all links/paths, current trusted CI and mergeability; document unresolved gates without percentages. Let the human maintainer decide to accept or request changes, never self-merge.
