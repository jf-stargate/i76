# i76shell.dll — original shell research discovery index

**Track:** `i76shell` (independent original DLL). **Status:** historical-evidence discovery, *not* a shell behavioral promotion or completed original-instruction validation. **Inventory base:** protected `main` at `3f06c23744765a5b209e4363add0a28853371f2a` (2026-10-31). This index records what is discoverable at that commit; recheck `main` before a new investigation.

## Identity, authority, and boundary

- The original target is `i76shell.dll`, an x86/Win32 DLL loaded by `i76.exe`; it is **not** an engine subsystem or the separate `i76edit.exe` editor. Historical shell image base: `0x10000000`. The legacy export identifies `0x1001e260 ShellMain`, `0x1001da10 ShellWindowProc` and `0x10040040` DLL/CRT entry. These are original **addresses with historical Ghidra names**, not recovered original source symbols.
- Trust order: root [AGENTS.md](../../../AGENTS.md), [VERSION](../../../agent/protocol/VERSION), [BOOTSTRAP.md](../../../agent/protocol/BOOTSTRAP.md), [access.yaml](../../../agent/protocol/access.yaml), [schema registry](../../../agent/protocol/SCHEMA_VERSIONS.json), and [documentation workflow](../DOCUMENTATION_WORKFLOW.md) from a single pinned `main` SHA. Accepted publication protocol `1.0.4` and default research schema `1.2.0` enable `i76shell` (schema versions `1.0.0`/`1.1.0` remain supported for their original tracks). See merged [PR #53](https://github.com/jf-stargate/i76/pull/53); it authorized the track, **not** any historical shell result.
- **Ownership:** shell owns frontend state, mission/vehicle selection and serialization, `DATABASE.MW2` display resources, DirectPlay setup/browser/host/join activity and the **producer** writes to the launch/session block. Engine owns the DLL loading/callsite, callback implementations, recipient/interpretation of the launch block and subsequent resource/mission runtime. Engine NET owns in-game multiplayer behavior after handoff. The callback table points *into engine code*; a shell-side invocation is not proof of the callback's implementation or multiplayer packet behavior.
- The earlier [subsystem inventory](../SUBSYSTEM_INVENTORY_20261028.md) is a dated **architecture proposal**, not current policy: its statement that shell publication is not permitted was superseded by merged #53. Its former absence-of-runs observation was **independently rechecked** below.

### Shell → engine configuration and callback ABI (investigation-critical)

The [engine caller at `0x004022e0`](../../../snapshot/i76.exe/i76.exe_ghidra_state_snapshot_20260524_082734/decompile/004022e0_call_shell_main.c) resolves `ShellMain`/`ShellWindowProc` with `GetProcAddress`, constructs **27 callback pointers (0x6c bytes)** on its stack, passes callback table as **arg9** and launch/session block as **arg10**. The [shell callee `0x1001e260`](../../../snapshot/i76shell.dll/i76shell.dll_ghidra_state_snapshot_20260520_172239/decompile/1001e260_ShellMain.c) binds them as `DAT_10058198` and `DAT_100d2170`; [`0x1002f178`](../../../snapshot/i76shell.dll/i76shell.dll_ghidra_state_snapshot_20260520_172239/decompile/1002f178_bind_shell_launch_config_block_and_close_previous_directplay.c) also aliases the block to `DAT_100f231c`. These are cross-snapshot **static** observations; do not turn names, assumed argument purposes or field labels into tested semantics.

| Byte offset in launch block | Shell producer / engine consumer contract candidate |
| --- | --- |
| `+0x00`, `+0x04` | Flags and shell/session mode; host/join paths write these. Bit `0x20` is mirrored from the incoming flags into `DAT_100d218c`. |
| `+0x08`, `+0x0c` | Session/DirectPlay pointer and player ID candidates; prior-session cleanup uses them. Exact ownership/ABI type remains open. |
| `+0x4e`, `+0x5d` | Resource path and mission filename buffers; shell formats or selects them; engine later builds a selected mission/resource path using `+0x4e`. Size/bounds and overlap assumptions require instruction tests. |
| `+0x6c`, `+0x70` | Engine copies a scalar and up to `0x1e` bytes of shell session text on a return-state-specific path. |
| `+0x90`, `+0x94`, `+0x98` | Candidate session descriptor fields and a `0x66`-dword descriptor payload; shell host/join fills, engine copies payload into its globals on one observed path. |

The engine's [`00404d20`](../../../snapshot/i76.exe/i76.exe_ghidra_state_snapshot_20260524_082734/decompile/00404d20_copy_shell_session_text_block.c), [`00404d50`](../../../snapshot/i76.exe/i76.exe_ghidra_state_snapshot_20260524_082734/decompile/00404d50_get_shell_selected_map_or_session_scalar.c) and [`00404d60`](../../../snapshot/i76.exe/i76.exe_ghidra_state_snapshot_20260524_082734/decompile/00404d60_copy_shell_session_descriptor_block.c) describe **engine-owned** downstream accessors. `ShellMain` returns `3` for an observed launch-message path and `0xff` for cancellation/exit; the engine checks the **low byte** against `0xff` and has additional `g_shell_return_state` paths. Treat interpretations of other enums and downstream launch effects as **unresolved**. In particular `0x004022e0` invokes game-owned callbacks such as table `+0x08 → 0x004b2b30` (resource registration), `+0x14 → 0x004b58a0` (vehicle definition) and `+0x44 → 0x00470f90` (disc prompt): the shell calls the table, but the engine defines their bodies and effects. Use [the historical callback table](../../../ref/game/i76shell.dll_reference.md#42-callback-table-from-i76exe) as a search map, and validate each target at the original engine address.

## Unresolved questions and ranked bounded original-instruction investigations

Each task needs measured input provenance before publishing a `1.2.0` run; emulated Win32/DirectPlay callbacks must be separately labeled and instrumented. Neither a private executable nor Ghidra project belongs in the public PR.

1. **P1 — ShellMain return and cleanup fork.** Execute the original `0x1001e260` message-loop/exit slice with controlled `WM_QUIT`/shell messages and stubbed services. Capture branch/return value (`3`/`0xff` and other cases), callback invocations, object/heap/session releases and repeat-invocation differences. Separately compare the original `0x004022e0` return discriminator. *No claim of actual Win32 execution with stubbed services.*
2. **P2 — Launch-block producer/consumer offset parity.** Reproduce single-player `0x10016a20`/`0x10016b50` and host/join `0x1002f368`/`0x1002fcd8` bounded writes with sentinel-filled `arg10`, then independently original-instruction-test engine `0x004022e0` consuming the same controlled data. Record exact byte ranges, bounds, flag transitions, aliasing and conditional copy paths. Never conflate injected callback effects with verified game behavior.
3. **P3 — Callback ownership and ABI.** Trap each shell indirect call through `DAT_10058198` with an instrumented 27-entry table; establish call frequency, argument/return conventions and reachable shell branches for a chosen menu-to-launch path. Investigate **engine** target bodies in an explicitly separate `i76exe` task/cross-track handoff; do not assign them to shell.
4. **P4 — DirectPlay failure/teardown transitions.** Native-execute narrowly selected `0x1002f178`/`0x1002e9b7`/`0x1002f368`/`0x1002fcd8` slices against explicit deterministic DirectPlay stubs (success, failed create, missing session/player, cancellation), recording handle and player ownership, descriptor-byte writes and teardown idempotence. Engine NET packets remain out of scope.
5. **P5 — Resource load/selection boundaries.** Execute original `0x10007fd0`/`0x10008240`/`0x10008320` against bounded lawful test records, distinguish parser/allocator failures from independent Python-decoder results, and isolate `0x100196b0` records 33–35 only if their UI consumer (`0x10019f40`) needs further fidelity.
