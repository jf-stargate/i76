# RND-v1 — subsystem completion and acceptance contract

**Status: proposed completion criteria; not an original-binary finding, promotion, project end-state ratification, or authorization to maintain a reconstructed renderer.** Prepared 2026-10-29 PDT from accepted `main` `2ec6f3bdb80d5858e87836097af776bd6fc98c20`. **Binary research track:** `i76exe`; **functional research owner:** [RND](RND.md). **Project dependencies:** [OBJ-02, CAP-CAMERA-01 and CAP-SLICE-01](../CAPABILITY_ROADMAP.md); [RND worker investigations](../RND_SUBSYSTEM_MILESTONES.md); [project objectives/strategic decisions](../PROJECT_OBJECTIVES.md).

This document defines **what completion means**, not an instruction to research every rendering routine. Milestones are instruments for satisfying its gates. Merging a research run or passing repository `integrity` is not, by itself, a subsystem completion decision. RND-v1 is a finite representative slice; unimplemented or undiscovered behavior **outside the explicitly agreed slice** is not an implicit blocker.

## Proposed RND-v1 outcome and bounded scene

**Target:** reproduce an authenticated, inspectable original camera-to-image pipeline for one controlled retail M06 scene containing **at least one authentic stock bus or GTSi vehicle plus an identifiable M06 environment/terrain region**. The scene must be expressible as deterministic source fixtures and two distinct camera/vehicle configurations producing distinguishable output. The intended future maintained renderer should produce a measurable framebuffer/image using source-backed geometry and material data with source-to-output validation. This **does not require** capturing the full retail Windows game loop or every original peripheral service.

**Provisional fixture proposal (not a claim of existing evidence):** use one selected stock vehicle and M06 resources already individually researched; a 640×480 fixed viewport and a single original software-rendering path are suitable initial validation parameters because original camera tests have used controlled 640×480 setup. The precise viewport, camera coordinates, scene snapshot, asset inventory, backend, source oracle and acceptable error thresholds must be **pinned in a reviewed fixture/acceptance decision before reporting a gate complete**. Prior controlled tests alone do not establish that this scene can already render. Other render modes/resolutions may follow in RND-v2.

**Minimal scenario matrix (finite, mandatory for v1):**

| --- | --- | --- | --- |

| **SC-RND-02** | Same authenticated world object and measured view with one visible and one empty/outside-frustum condition | Original `00457FF0` visits object and produces an identifiable spatial record where the visibility predicate permits it; negative case does not produce that eligible record | Empty-world and culling controls; original insertion address, record kind/owner/bucket; no test-authored queue node |
| **SC-RND-03** | Original-produced eligible work record, verified GEO and at least one relevant original material or texture descriptor | Original `0048FAC0` consumes the **same** record in one emulator state and reaches genuine geometry / material / polygon submission with observable primitive identity | Same-record pointer and queue-clearing checks; zero-face or rejected primitive; do not infer texture pixels from TMT name alone |
| **SC-RND-04** | At least one identifiable stock-vehicle face and one M06 terrain/environment contribution, with a source-backed view | Native clip/draw or other backend-correct original behavior yields independently interpretable draw/primitive output, and a deterministic framebuffer/image is available as an eventual comparison oracle | Culled/clipped case, material/UV checks and valid output buffer ownership; no accepted pixel claim from submitter counts |

Before claiming RND-v1 integrated or product completion, close these coverage holes with further bounded investigations or *explicitly* revise the v1 scenario in a reviewed acceptance PR.

| **RND-INTEGRATED-v1** (original-path integration complete) | Research gates plus **RND-I1** (SC-RND-01..04 in one same-state source-backed original run, with interpretable output boundary) | Original camera → visibility → work queue → GEO/material → clip/draw/result is joined in a reproducible controlled original-instruction scenario, with no fabricated internal queue/scene state; this remains **not** complete WinMain or retail pixels unless verified | **Open.** Prior camera and renderer paths are separate bounded tests |
| **RND-PRODUCT-v1** (maintained renderer complete) | Research/integration contracts plus **RND-P1**, **separate explicit implementation authorization** and SC-RND-01..05 acceptance | Independently maintained rendering implementation produces a validated camera-to-image M06 v1 scenario and passes the declared regression suite at the approved quality/performance bounds | **Not authorized / not begun** by this planning record |

**Language discipline:** never say simply “RND is complete.” Say “RND-RESEARCH-v1 accepted”, “RND-INTEGRATED-v1 accepted” or “RND-PRODUCT-v1 accepted”, with the accepted review commit and explicitly limited scenario. An implementation may use an alternative validated original oracle only if the maintainer formally approves the substituted evidence and revised gate beforehand.

## Measurements and acceptance thresholds

The numerical and visual acceptance test must be able to decide **pass / fail**, not merely display “reasonable looking”. The following are mandatory fields of the future pinned SC-RND fixture manifest:

- Retail PE, original resource archive and derived scene fixture SHA-256 identities; private input storage references; original/controlled camera and vehicle transforms; selected software/hardware path; exact viewport/pixel/color format.
- Authoritative source for each expected camera matrix/translation, world-object visible/culled outcome, original work record owner/type/bucket, primitive identity/vertex/UV/material and any raster or framebuffer output. Explicit **original-instruction**, **retail execution** or **independent model** provenance; no mixing without labels.
- Actual numeric comparison representation (float/double decoding, coordinate systems, ULP/absolute/relative thresholds as appropriate), geometry/visibility discrete comparisons, image comparison or perceptual metric, mask/exclusions if any, and exact source-backed justification for each tolerance.
- Predeclared pass/fail cases, known acceptable deviations, all negative controls, seeded service/time behavior, source fixture version and independent verifier commands. Changing thresholds **after** observing implementation results requires a reviewed versioned change and an accompanying old/new regression comparison.

There is **no current source-backed universal pixel, camera-pose or x87 parity tolerance**. This document does not invent one. The missing reference capture/threshold decision is a tracked gating prerequisite, not permission to declare product completion based on subjective resemblance.

The ledger is **closed to arbitrary expansion**: a newly discovered issue may be recorded, but a new blocking gate can be added only if it prevents an existing mandatory SC-RND scenario and is accepted in a reviewed change. Interesting unrelated routines belong in v2/backlog, not the current completion test.

## Explicit RND-v1 exclusions

For this first representative scenario, completion does **not** imply all missions/vehicle families, every camera mode, weather/time-of-day, shadows/lighting variants, particle systems, explosions, lens effects, headlight/type-10 paths, UI/HUD, cutscenes/video playback, network/multiplayer, all software/D3D backend permutations, arbitrary resolutions, comprehensive texture animation, resource lifetime/teardown or full pixel-bit identity with the original graphics hardware. Some excluded behaviors may still affect the chosen M06 fixture: if an excluded feature becomes demonstrably mandatory for an in-scope case, the maintainer must either close that exact gap, select a different authenticated fixture, or amend this contract; it cannot be silently ignored.

M06 terrain/surface **visual contribution** is in scope; proving general polygon *physical collision* is TER/VEH work and is not an RND completion prerequisite. Complete original selected post and WinMain dispatch are CAP-CONTROL-01/CAP-SLICE-01 dependencies, not substitutes for original RND producer/consumer research.

## Completion decision, no automatic close

1. **Fix scope before final evaluation:** human maintainer reviews this RND-v1 proposed acceptance, explicitly accepts or edits the scenario matrix, stage boundaries and deferred functionality. This merged document alone is not a ratified project end state or approval to build replacement code.
2. **Evidence collection:** each Codex worker publishes its one immutable `agent/runs/i76exe/<run_id>/` PR. The maintainer accepts the run after scientific review and protected CI; the separate documentation steward reconciles selected findings into `agent/promotions/` and `manual/reference/`. Negative evidence may close a *research question* but not a *positive* acceptance test.
3. **Acceptance matrix:** a separate maintainer-reviewed `RND_v1_ACCEPTANCE_RECORD.md` (or equivalent future reviewed decision) records for every SC-RND scenario and gate its `pass / partial / blocked / failed / deferred` status, reviewed source PR/merge SHA, approved fixture, verifier version, quantitative output and explicitly excluded claims. Do not modify a research run to update that status.
4. **Decision:** declare **RND-RESEARCH-v1** only if RND-R1 and RND-R2 pass with promoted key contracts; declare **RND-INTEGRATED-v1** only if research prerequisites and RND-I1 pass; declare **RND-PRODUCT-v1** only after explicit implementation authorization and RND-P1 plus the two-view image suite pass. `integrity` checks publication structure/security but is not behavior validation. The human maintainer signs off each stage with a reviewed PR.
5. **If a gate cannot pass:** label it blocked/inconclusive, publish what is learned, choose the smallest testable prerequisite, or **explicitly** revise the v1 scope after review. No silently relaxed tolerances, inferred original pixels or “complete” declaration by PR count.
