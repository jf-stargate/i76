## 1. Functional boundary: what RES owns and does not own

RES is the **acquisition/identity/retention interface** from a logical filename or registered key to a resource record and byte/handle ownership; it encompasses the original loose-file search, ZFS/ZIX-facing registered lookup, PIX/PAK indexed-members, normalizing lookup keys, loaded-resource cache, buffer ownership and release, and delivery of ACT/LUM/texture bytes. These are *functional* boundaries, not proven original translation units. There is no established single all-purpose resource-manager class or uniform cache record.

```text
MLD (BWD2/WRLD/ODEF/LDEF and suffix decision) ─┐
VEH (VCF→VDF/VTF/WDF/CDF) / OBJ / GEO (SDF, parts) ├─> RES key/path/registry
TER (TDEF/ZMAP/ZONE and TER sidecar requests) ────┤       ├─ loose / registered ZIX→ZFSF record
RND/GEO (ACT/LUM, TMT frame, MAP/M16/VQM/CBK) ──┘       ├─ PIX index → PAK member
                                                          └─ loaded cache / bytes / release
RES bytes → MLD parses descriptors; OBJ owns world identities; GEO interprets mesh/material;
            VEH builds vehicle runtime; TER maps terrain; RND owns palette/context,
            shade generation, clipping, raster and framebuffer.
```

**MLD** owns BWD2 parsing, WRLD/VCF/SDF descriptor semantics and which filename suffix a mission/class asks for; RES owns resolving and returning that name, not interpreting a successful BWD2 parse. **OBJ** owns live world object/registry lifetime, not the underlying file buffer. **GEO** owns construction of runtime geometry and interpretation of GEO sections, TMT/VTF relationships and pixel formats; RES owns supplying referenced bytes and any *separate* resource cache. **RND** owns backend selection, palette context, shade-table creation and pixels, though a source loader may deliver ACT/LUM inputs. **TER** owns grid/page/sampling after resource acquisition. `i76edit.exe` is an independent binary, not automatically an original-game resource provider; editor-produced resources are cross-format evidence only.

Distinguish at least **five namespaces**: (a) on-disk loose filename; (b) ZFSF directory record/possible ZIX registration key; (c) PIX row name and companion PAK member offset/size; (d) logical VTF/GEO material slot name versus TMT descriptor/frame basename; (e) in-memory loaded-resource record, GEO handle and per-object owner slot. A basename match across these namespaces does **not** prove identical lookup precedence, pointer ownership or lifetime. A missing loose `.geo` is not absence from the indexed archive; conversely, a Python resolver hit is **not** an original retail lookup.

Historical source policy: mission 8-byte fixed labels plus caller-selected suffix lead to `.vcf` for selected ODEF vehicle classes (0x01/0x08/0x09), `.sdf` for static ODEF/LDEF, SOBJ children often `.geo`, VCFC references to `.vdf/.vtf/.wdf`. The exact caller-specific exceptions (e.g. spawn/regen) and BWD2 semantics belong to MLD/OBJ and must be checked against [model reference](../../../ref/model_format/i76_vehicle_model_format_and_extraction_reference.md) and [mission execution](../../../ref/mission_execution/README.md); this historical extraction policy is **H/D**, not one proved retail resolver contract.

## 4. ACT/LUM source selection handoff — M-RND-12 starting map

**Critical anti-misidentification:** PR #81's authenticated `m02.act` is a genuine **B** ZFS resource but **not** proven the ACT selected by original M06 WRLD, not proven associated with the stock-bus scene and not equivalent to an ACT resolved/loaded by retail code. Its first RGB entry (1,1,1) is kept unchanged in that test; some original update callers instead force entry zero to black or value 1. Do not silently retrofit any of these variants into M06 or into the GEO constructor.

## 7. Open dependencies / “do not infer” checklist

1. Core RES loose/ZFS/ZIX/PIX lookup *precedence*, resource registration timing, normalization corner cases, cache records, invalidation/refcounts, request failures and retry remain **U**. The historical map provides addresses, not a full verified ABI. Confirm exact original opcodes and calling conventions before patching a harness boundary.
2. Original ZFSF LZO and PIX/PAK index/payload *consumer execution* must be distinguished from extraction by `scripts/game/` or a substituted indexed-file provider. A ZFS member digest validates a fixture, not which retail source was chosen.
3. `004469A0` geometry pointer reuse and `0044A0B0` VQM slot rebind do **not** imply end-to-end core cache behavior or release/free. Different scope, address space and tested fixture.
4. Original M06 material property copy at `004B8A10` is not ACT/LUM selection/installation. PR #81's `m02.act` authentic *bytes* and original shade calculation do not prove M06 selection, GEO material color, true RGB appearance, or full palette update.
5. Context pointer, `005DD2C4` callback/backend, `0048DC60` update, `004791E0` table, `004796A0` GEO-time nearest-color and final `0047CB00` indexed consumer are different ownership boundaries. Preserve their observed ordering, substitutions, and missing calls instead of treating successful raster stores as authentic renderer color.
6. Separate follow-ups: [M-RND-13](../RND_SUBSYSTEM_MILESTONES.md) whole-table/native-RET and optional LUM copy; M-RND-15 authentic GEO RGB binding *after* M-RND-12; M-RND-14 M06 terrain native command/spans independently; RND-v1/genuine image gates remain open. Editor/material/exporter interpretations are useful controls, not retail runtime proof.
